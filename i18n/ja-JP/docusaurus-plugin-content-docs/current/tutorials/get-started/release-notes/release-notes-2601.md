        ## Milvus v2.6.x の新機能\{#milvus-v26x-new-features}

        - **タイムゾーン対応のタイムスタンプサポート** — `TIMESTAMPTZ` データ型をサポートし、手動でのタイムゾーン処理なしで、グローバルに一貫したタイムスタンプの保存、比較、フィルタリングを可能にします。詳細については、[TIMESTAMPTZ フィールド](./use-timestamptz-field)を参照してください。

        - **ハイライター** — カスタマイズ可能なタグとフラグメントレベルのコンテキストで一致する用語に注釈を付け、full text searchの結果を解釈しやすく、デバッグしやすくします。詳細については、[テキストハイライター](./text-highlighter)を参照してください。

        ## 関数とモデルの推論\{#function-and-model-inference}

        Zilliz Cloudにおけるモデルベースの埋め込みおよび再ランキング関数のパブリックプレビューと、Zilliz Hosted Modelsのプライベートプレビューを発表できることを嬉しく思います。このアップデートにより、ユーザーは生のテキストをZilliz Cloudに直接挿入でき、システムが埋め込みと再ランキングを自動的に処理して、最も関連性の高い検索結果を保証することで、AI開発プロセスを合理化します。

        OpenAI、Cohere、VoyageAIなどのトップティアのサードパーティプロバイダーからモデルを選択したり、Zilliz Cloudに直接モデルをホストしたりできるようになりました。

        - **モデルベースの埋め込み**: collection作成時にテキスト埋め込み関数を定義します。設定後、Insert、Upsert、またはImportを介して生のテキストを取り込むだけで、Zillizが埋め込みの生成と保存を自動的に処理します。検索中、システムはテキストを密なベクトルに変換し、効率的なANN検索を行います。詳細については、[テキスト埋め込み関数の概要](./undefined)を参照してください。

        - **モデルベースの再ランキング**: ニーズに最適な再ランキングモデルを選択し、特定のユースケースに最も関連性の高い検索結果が優先されるようにします。詳細については、[モデルベースのランカー](./model-ranker)を参照してください。

        - **Zilliz Hosted Models (プライベートプレビュー)**: Zillizインフラストラクチャに直接完全に管理されたモデルインスタンスをデプロイし、データ転送費用なしで安定した高性能な推論を保証します。Zilliz Cloud環境でモデルを実行することで、データはプライベートネットワーク内に留まり、プライバシーの強化と超低レイテンシーを保証します。詳細については、[ホスト型モデル](./hosted-models)を参照してください。

        さらに、サードパーティモデルとの統合を合理化するために、**サードパーティモデルプロバイダー統合**を導入しました。この機能により、Zilliz Cloud内でAIモデルの認証情報を管理し、アプリケーションコードを変更することなくいつでもAPIキーをローテーションできるため、柔軟で安全な統合が保証されます。詳細については、[モデルプロバイダーとの統合](./integrate-with-model-providers)を参照してください。

        ## 動的レプリカオートスケーリング\{#dynamic-replica-autoscaling}

        需要が変動する高QPS環境向けに設計された主要機能である**インテリジェントレプリカオートスケーリング**を導入します。これは、リアルタイムのトラフィックパターンに基づいてクラスターのreplica数を自動的に調整します。

        - **負荷適応型スケーリング**: トラフィックが多い期間にはreplicaを自動的にスケールアップし、需要が低い期間にはスケールダウンすることで、パフォーマンスとコストの両方を最適化します。

        - **ゼロタッチの信頼性**: シンプルなリソースガードレールにより、システムは予測不可能なトラフィックスパイクを自動的に処理し、手動介入なしで一貫したパフォーマンスを保証します。

        詳細については、[レプリカのスケール](./manage-replica#dynamic-scaling)を参照してください。

        ## Cronによる高度なスケジュールスケーリング\{#advanced-scheduled-scaling-with-cron}

        複雑で予測可能なビジネスサイクルをオーケストレーションするために、スケジューリングエンジンをアップグレードしました。業界標準のCron式を使用して、CUとReplicaの両方で正確なスケーリング戦略を自動化できるようになりました。

        - **柔軟なスケジューリング戦略:** 基本的な日次スケジュールを超えてください。標準のCron構文（例：`0 9 * * 1-5`）を利用して、「月末のみスケールアップ」などの複雑なルールを定義します。

        - **マルチスケジュールロジック:** 同じクラスターに対して独立した階層化されたスケジュールを設定し、ピーク時の平日とオフピーク時の週末のリソースプロファイルを調整して、ビジネスの実情に合わせて効率を最適化できます。

        詳細については、[クエリCUのスケール](./scale-query-cu#scheduled-scaling)および[レプリカのスケール](./manage-replica#scheduled-scaling)を参照してください。

        ## グローバルクラスタープライベートプレビュー\{#global-cluster-private-preview}

        Zilliz Cloud Business Critical Planのグローバルクラスターのプライベートプレビューを発表できることを嬉しく思います。

        グローバルクラスターは、プライマリクラスターとクロスリージョンのセカンダリクラスターを自動レプリケーションのためにリンクすることで、複数の地理的リージョンにわたる統合されたデータベースアーキテクチャを作成します。このソリューションは堅牢な災害復旧（DR）を提供し、リージョンの停止が発生した場合でも、ミッションクリティカルなアプリケーションが回復力を維持し、データが永続的であることを保証します。

        - **自動グローバルデプロイメント:** システムは、プライマリ-セカンダリトポロジのシームレスなオーケストレーションをワンクリックで処理し、自動データレプリケーションチャネルを使用してグローバルクラスターを単一ステップでプロビジョニングできます。

        - **シームレスなDR拡張:** アクティブな本番インスタンスへのセカンダリクラスターの動的な追加をサポートします。サービスの中断やダウンタイムなしで、実行中の専用クラスターをマルチリージョンのグローバルアーキテクチャにスムーズにアップグレードできるようになりました。

        - **強化された可観測性:** 新しいグローバルトポロジダッシュボードは、クラスター階層の統合ビューを提供します。1つのインターフェースから、リアルタイムのレプリケーションレイテンシーとリージョン間の同期ステータスを監視できるようになりました。

        **近日公開:**
        回復力ツールキットを拡張しています。次のフェーズでは、リージョンレベルの停止時の自動切り替えのためのフェイルオーバーと、SDKトラフィックを再ルーティングするグローバルエンドポイントが導入され、リカバリ時間目標（RTO）が大幅に短縮されます。

        詳細については、[グローバルクラスターの説明](./global-cluster-explained)、[グローバルクラスターの作成](./create-global-cluster)、および[グローバルクラスターの管理](./manage-global-cluster)を参照してください。

        ## BYOC - フルオートスケーリングスイートがSaaSと連携\{#byoc-full-autoscaling-suite-aligns-with-saas}

        **Bring Your Own Cloud (BYOC)** デプロイメントは、Zilliz Cloudオートスケーリングエコシステム全体をサポートするようになりました。このアップデートにより、BYOCはSaaS製品と連携し、以前にリリースされたすべての最適化（自動スケールダウンなど）と**最新の機能**にアクセスできるようになります。

        - **動的スケーリング:** CUとReplicaの両方で利用可能で、システムはリアルタイムの負荷に基づいてリソースをインテリジェントに調整し、パフォーマンスとコストを最適化します。シンプルなMin/Max設定が可能です。

        - **スケジュールスケーリング:** 新しいアドバンストモードを完全にサポートします。ユーザーは、標準のCron式とマルチスケジュールロジックを活用して、複雑で予測可能なビジネスサイクルに合わせて正確なリソース調整を自動化できるようになりました。

        詳細については、[クエリCUのスケール](/docs/byoc/scale-cluster)および[レプリカのスケール](/docs/byoc/manage-replica)を参照してください。

        ## BYOC - サポートとトラブルシューティングのアクセス制御\{#byoc-support-and-troubleshooting-access-control}

        データプレーンへの運用アクセスを管理します。Zillizエンジニアが明示的に許可された場合にのみ、インフラストラクチャにアクセスできるようにします。

        - **ジャストインタイム (JIT) 特権:** トラブルシューティング期間中に一時的なアクセスを許可し、解決後すぐに取り消します。

        - **運用分離:** アクセスを取り消すことで、重要な可観測性パイプライン（メトリクス、ログ、アラート）を中断することなく、厳格な障壁を作成します。

        - **ガバナンスとコンプライアンス:** すべてのアクセス許可と取り消しは、完全な説明責任とセキュリティレビューのために監査ログに不変的に記録されます。

        詳細については、[AWSへのBYOCデプロイ](/docs/byoc/deploy-byoc-aws#technical-support-access)、[AWSへのBYOC-Iデプロイ](/docs/byoc/deploy-byoc-i-aws#technical-support-access)、および[GCPへのBYOCデプロイ](/docs/byoc/deploy-byoc-gcp#technical-support-access)を参照してください。

        ## 強化\{#enhancements}

        - **Collection TTLとAutoID設定**: Collection TTLとAllow insert AutoID設定をCollection Overview GUIから直接監視および変更できるようになりました。詳細については、[Collection TTLの設定](./set-collection-ttl)および[Collectionの変更](./modify-collections)を参照してください。

        - **データインポート**: JSON Lines形式（.JSONLおよび.NDJSON拡張子）のサポートが利用可能になりました。詳細については、[JSON/JSON Linesファイルからのインポート](./data-import-json)を参照してください。

        - **Milvusエンドポイント移行**: **Geometry**および**Struct**データ型をサポートし、空間形状と深くネストされた属性を持つcollectionのシームレスな移行を可能にします。

        - **ジョブ詳細ビュー**: サイドドロワーUIが刷新され、ナビゲーションが改善され、ユーザーエクスペリエンスが向上しました。

        - **BYOC - S3バケットサポート**: 専用のS3バケットを持つクラスターをデプロイできるようになり、きめ細かなデータ分離と独立したライフサイクル管理が提供されます。

        - **BYOC - AWS KMS統合**: S3バケット暗号化のためのAWS KMS (CMEK) 統合が追加され、厳格なセキュリティコンプライアンス基準を満たします。

        - **強化されたメトリクスダッシュボード**: CUとReplicaのスケーリングに最適な利用レベルを特定するのに役立つ視覚的なしきい値ガイドラインが追加されました。

        - **RESTful APIとTerraformの強化:** [オートスケーリング](/reference/restful/modify-cluster-v2)、[クロスリージョンバックアップ](/reference/restful/create-backup-v2)、[クラスター作成のための階層型ストレージ](/reference/restful/create-dedicated-cluster-v2)、および[プロジェクト作成のためのBusiness Critical Plan](/reference/restful/create-project-v2)をサポートし、災害復旧とストレージ管理を改善し、より効率的な自動化プログラミングを可能にします。
