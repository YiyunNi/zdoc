# リリースノート (2024年1月18日)

Zilliz Cloud は、データインポート機能のユーザーエクスペリエンスを最適化し、階層型パーミッションを持つAPIキーを改良し、メトリクスとアラートメカニズムを強化しました。

## Milvus互換性\{#milvus-compatibility}

このリリースは、**Milvus 2.2.x** および **Milvus 2.3.x (ベータ版)** と互換性があります。

## データインポート\{#data-import}

最新リリースでParquetデータ形式のサポートを発表できることを嬉しく思います。ユーザーエクスペリエンスを向上させるため、PyMilvusライターユーティリティを導入しました。これは、ユーザーがJSONまたはParquet形式でファイルを簡単に作成し、シームレスなデータインポートを支援する強力なツールです。詳細については、[データインポート](./data-import)をご覧ください。

## APIキー\{#api-key}

このリリースで、Zilliz Cloud は [APIキー](./manage-api-keys) の統一されたデザインを導入しました。各ユーザーは、単一の統一されたAPIキーを使用して、Zilliz Cloud プラットフォームと複数のクラスターにアクセスできます。

Zilliz Cloud のパーミッション設計は、RBAC (Role-Based Access Control) の原則に従っており、オペレーション層とデータ層の2つの層に分かれています。オペレーション層では、ロールがクラスター、プロジェクト、ユーザー、請求などのリソースの操作パーミッションを管理します。データ層では、ロールがデータの追加、削除、変更、クエリの機能を制御することに焦点を当てています。

![V6ZhbOu0go1AORx0dxFcELQ3ndd](https://zdoc-images.s3.us-west-2.amazonaws.com/v6zhbou0go1aorx0dxfcelq3ndd.png "V6ZhbOu0go1AORx0dxFcELQ3ndd")

オペレーション層では、Zilliz Cloud は4種類のロールをサポートしており、そのうち組織オーナー、プロジェクトオーナー、プロジェクトメンバーの3つが一般的に使用されるロールです。

- 組織オーナー: 組織設定、支払い方法と請求の管理、APIキー、組織内のすべてのプロジェクト、および関連リソースを含む、組織に対する完全な管理権限を持ちます。

- プロジェクトオーナー: プロジェクト設定、プロジェクト内のすべてのクラスター、APIキー、およびその他の関連リソースを含む、プロジェクトに対する完全な管理権限を持ちます。

- プロジェクトメンバー: プロジェクト内のすべてのクラスターに対する読み取りおよび書き込みパーミッションを持ち、クラスターの詳細を表示し、collectionとインデックスを管理できます。

データ層では、Zilliz Cloud は管理、書き込み、読み取りのデータパーミッションを制御するために、Admin、Read-Only、Read-Writeの3つの組み込みロールを提供します。Zilliz Cloud は、ユーザーがカスタムロールを作成することを可能にします。これらのカスタムロールは、特定のcollection、partition、または操作に対するパーミッションを定義でき、Zilliz Cloud を使用する際の最小データパーミッションの原則を保証します。詳細については、*ドキュメント*を参照してください。

## メトリクスとアラート\{#metrics-and-alert}

このリリースでは、[メトリクスボードとアラートシステム](./metrics-and-alerts)をリファクタリングしました。新バージョンでは、広範囲のメトリクスを監視する機能が追加されました。

- リソース使用量メトリクス: CU (Compute Unit) 計算リソース使用率、CU容量使用率 (満杯度)、および全体的なストレージ使用量の詳細なビューが含まれます。

- パフォーマンスメトリクス: 検索/クエリのスループットとレイテンシ、データ挿入の効率 (スループットとレイテンシの両方)、およびリクエスト失敗率などの重要なパフォーマンス指標を追跡します。

- データメトリクス: collectionの数、entityの総数、検索のためにloadされたentityの数、およびインデックス化されたentityの数に関する洞察を得ます。

さらに、強化されたアラートシステムにより、上記のすべてのメトリクスに対してカスタマイズされたアラートルールを設定できます。これにより、Query Per Second (QPS) レートが1000を超えた場合や、CUの満杯度が70%を超えた場合など、システムの状態とパフォーマンスについて常に情報を受け取り、積極的に対応できるようになります。

## 強化点\{#enhancements}

このリリースには、一連の強化点も含まれています。

- いくつかのウェブコンソールページのユーザーエクスペリエンスが向上しました。

- 安定性の強化: 既知の問題に対処し、サービスの信頼性をさらに向上させました。
